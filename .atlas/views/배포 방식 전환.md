# Atlas 배포 방식 전환

> **Last Updated**: 2026-02-06
> **Status**: Draft
> **Audience**: Dev / Maintainer
> **Intent**: atlas.py 복사 배포를 pip 패키지 기반 CLI로 어떻게 전환하는가?
> **Scope**:
> - In: 배포/설치/업데이트 방식 변경, 빌드 체인 단순화
> - Out: .atlas/ 폴더 구조 변경 (기존 유지)
> **Refs**: @REQ-DIST-002, @CQ-DIST-002

---

## Summary

현재 각 프로젝트에 `atlas.py`를 복사하는 방식은 업데이트 전파가 어렵고 빌드가 복잡하다.
pip 패키지로 전환하면 `pipx install`로 설치하고 `atlas` 명령어로 실행한다.
프로젝트 산출물 구조(.atlas/...)는 기존과 동일하게 유지한다. (@REQ-DIST-002#Decision)
전환은 Phase 1(stickytape 제거) → Phase 2(pip 패키지)로 단계적 진행한다.

---

## Flow Map

```
[Phase 1]                    [Phase 2]                    [완료]
stickytape 제거              pip 패키지 전환              프로젝트 정리
     │                            │                           │
     ▼                            ▼                           ▼
 build.py 단순화            pyproject.toml 작성         atlas.py 제거
 placeholder 치환만         src/memory_atlas/ 구조      (또는 thin wrapper)
 defaults 인라인 유지       atlas entrypoint 등록       pipx/uv로 설치
```

---

## Key Decisions

| 단계 | 결정 포인트 | 분기 |
|------|-------------|------|
| Phase 1 | defaults 처리 | 인라인 유지 (A) vs JSON 분리 (B) → **A 권장** |
| Phase 2 | 패키지 구조 | 단일 cli.py vs 모듈화 → **모듈화 권장** |
| 호환성 | 기존 프로젝트 | 완전 제거 (A) vs thin wrapper (B) → **A 권장** |
| 설치 방식 | 도구 선택 | pipx vs uv → **둘 다 지원** |
| defaults 로딩 | 우선순위 | 프로젝트 로컬 → 환경변수 → 패키지 내장 |

---

## Failure Modes

| 실패 유형 | 증상 | 해결 |
|-----------|------|------|
| 구조 불일치 | 전환 후 .atlas/ 구조 다름 | init 결과 비교 테스트 필수 |
| defaults 누락 | 템플릿 생성 실패 | 패키지에 defaults.json 포함 확인 |
| PATH 미등록 | `atlas` 명령 못 찾음 | pipx ensurepath 실행 |
| 버전 혼재 | 프로젝트별 다른 버전 | thin wrapper 제거, 단일 설치로 통일 |

---

## 전환 체크리스트

### 기능 동일성
- [ ] `atlas init` 결과 폴더/파일 구조가 기존과 동일
- [ ] `atlas doctor`가 동일한 경고/오류 재현
- [ ] `atlas sync`가 기존 프로젝트에서 동일하게 동작

### 배포/업데이트
- [ ] 프로젝트별 atlas.py 복사 없이 실행 가능
- [ ] `pipx install` 후 `atlas --help` 정상
- [ ] (선택) thin wrapper 프로젝트에서 호환 동작 확인
